# Cache contract and tested boundaries

Every application request supplies a verified tenant, user, allowed-document set and permission epoch. The application derives the current scope; callers must not provide a stored scope as a substitute. Scope includes the complete candidate-corpus digest, exact generator and embedding revisions and prompt version. Model snapshot bytes are verified against the experiment lock. Each returned entry also passes current source checks. These checks apply equally to answers and passages.

Whitespace-only normalization and Unicode NFC retain punctuation, case, entities, dates, numbers and negation. They may miss harmless variants but do not deliberately merge them. Semantic search uses normalized vectors and a cosine threshold. A lexical guard compares numeric tokens and selected negation words. It misses argument order and many entity substitutions. Neither this guard nor a similarity threshold establishes semantic equivalence.

The dictionary cache keeps an ordered LRU. FAISS uses an ID-mapped flat inner-product index with incremental insertion/removal. Search currently scans eligible entry metadata and searches the full FAISS index before applying scope eligibility; this is a small local implementation, not an optimized multitenant service. The exact cache checks source validity before exposing content. The framework treats cache insertion as a trusted internal operation.

SQLite signs each JSON payload with HMAC-SHA256 and requires an external key of at least 32 bytes. WAL transactions protect each write. Signed reads fail closed on modification or a wrong key. LRU access writes are persisted. A process crash between a durable insertion and subsequent capacity pruning can leave extra entries; restart prunes before serving. Whole multi-entry capacity enforcement is not a distributed atomic transaction. Recovery tests close and reopen storage; they do not simulate power loss or filesystem corruption.

The lock serializes in-process cache access. Generation runs outside it and concurrent misses can duplicate inference. No distributed lock, stampede suppression or linearizable cross-process cache protocol is provided. SQLite coordinates database writes, not the separate in-memory views of multiple processes. Source and authorization state are treated as a request snapshot. Concurrent source/ACL changes during a lookup are not tested or made transactional; an integrating application must provide consistent snapshots to avoid a check/return race.

Controlled fixtures test changed content, deletion, revocation, unknown authorization, tenant/user changes, permission epochs, model/prompt changes, expiration, LRU eviction, concurrent insertion, restoration, serialization and persisted-payload modification. Tests do not establish protection against stolen credentials, compromised trusted writers, malicious model weights, source prompt injection, timing side channels, key management failures or upstream changes not ingested into the corpus.

Exact compatible reuse is the stricter reference. Semantic answer reuse and permissive evidence fallback remain experimental. Evidence reuse retains generation but can omit the evidence needed by a new question. A correct cache hit can still repeat an incorrect baseline answer.
