# Agent control under limited evidence and compute

The study asks whether dynamic retrieval improves answers enough to justify its extra calls. The primary comparison holds the answer generator and candidate documents fixed while changing the controller. An agent can lose through poor search queries, invalid actions, repeated evidence, premature stopping, or a verification gate that rejects a correct answer.

## Reference audit and workflow

Project 1 compares retrieval methods on SciFact and FiQA. Its observed fusion gains and reranking losses discourage assuming that extra stages help. Project 2's original study uses FLAN-T5-small and small local partitions. Its upgrade evaluates FLAN-T5-base, Qwen, stronger retrieval, and grounding checks. The practical FLAN reference outperformed the structured Qwen system on its recorded samples. The upgrade also documents formatting failures and the distinction between NLI support and question relevance.

The repository contains research designs, execution notes, acquisition locks, staged selection, publication scripts, and preservation manifests. No standalone original master-workflow document or applicable AGENTS.md was found in the accessible repository or checked ancestors. The current master instruction supplies the workflow where prior files do not. Prior implementations and reports are read-only references. A hash manifest covers their non-data files and local notebooks. No cleanup is planned; the cleanup manifest records zero recovered bytes.

There are exactly two notebooks in this project: the executed local research notebook and its source-identical, output-free public copy. Builders refuse to replace an executed notebook. Execution failures are retained in ignored local storage. All experimental predictions are local checkpoints, with aggregate metrics published separately.

## Questions and measured contrasts

Related methods motivate the control choices. [ReAct](https://arxiv.org/abs/2210.03629) interleaves reasoning and external actions; this project retains bounded actions and observable evidence state without requesting private reasoning traces. [IRCoT](https://aclanthology.org/2023.acl-long.557/) studies retrieval conditioned on intermediate reasoning, motivating evidence-dependent follow-up queries. [Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389/) selects retrieval strategies according to question complexity; the deterministic comparator here instead uses source diversity and lexical coverage. [Self-RAG](https://arxiv.org/abs/2310.11511) trains retrieval and reflection behavior with special tokens. The present verifier uses an external NLI model and does not reproduce Self-RAG training or its results. These are related design choices, not benchmark replications.

| Question | Comparison or diagnostic |
| --- | --- |
| Does dynamic control help? | Fixed, rules, plan-and-execute, tool selection, verification-guided selection |
| When does another call help? | Annotated new-document gain after the first call; paired answer and evidence changes |
| Can a model select tools? | Valid actions and realized distribution over BM25, dense, fusion, reranking, lookup and title links |
| Does planning help multi-hop QA? | Plan-and-execute versus fixed and reactive control on HotpotQA |
| Is evidence missing or conflicting? | Empty results, source recall, generated-claim NLI entailment and contradiction diagnostics |
| Does verification improve stopping? | Prespecified support thresholds 0, 0.5 and 0.8, coverage and selective correctness |
| Are calls wasted? | Repeated-action rejection and duplicate-evidence call rate; these are proxies, not causal necessity judgments |
| Can agents recover from bad tools? | First-result empty, irrelevant and injected-instruction perturbations |
| Is the runtime justified? | Matched F1, p50/p95 latency, stage costs, tokens and process/GPU memory |
| Can rules compete? | A deterministic evidence-diversity and question-coverage rule against model control |

## Dataset decision and integrity

[HotpotQA](https://github.com/hotpotqa/hotpot) supplies questions, candidate paragraphs, answer strings, document titles and sentence-level supporting facts. The pinned Hugging Face validation snapshot is reused byte-for-byte from Project 2, with the original converted JSON hash checked. The candidate pool is the supplied distractor setting, not Wikipedia-wide retrieval. Titles are authentic document identifiers within a question; they are not globally unique passage IDs. Passage IDs are deterministic hashes of original title, sentence offset and text. Invalid original supporting-sentence indices are reported and omitted from the sentence-recall denominator without changing the source labels.

[SQuAD 2.0](https://rajpurkar.github.io/SQuAD-explorer/) supplies original answer spans and adversarial unanswerable questions. Every article in the previous local development release had been used by Project 2, so this project acquires the public v2.0 training release. Its SHA-256 is measured at acquisition, not supplied independently upstream. It is a complementary single-paragraph answerability task; success on it is not multi-hop tool-use competence. Both selected releases use CC BY-SA 4.0; raw text remains local.

SQuAD has original question IDs, article titles and paragraph positions rather than standalone document IDs. The loader derives `title:paragraph-index` identifiers and preserves the original question IDs, answer strings and offsets. Generative token counts cover planner, answer and claim calls, including returned decoder-start/end tokens. They exclude embedding, reranking and NLI tokenization; those models have separate latency and memory observations.

[MuSiQue](https://github.com/stonybrooknlp/musique) has compositional multihop questions and paragraph-support labels; [2WikiMultiHopQA](https://github.com/Alab-NII/2wikimultihop) includes structured reasoning annotations. They would strengthen external validity, but would require another acquisition, loader, annotation audit and evaluation budget. Neither is downloaded. This study prioritizes fresh controlled partitions of two audited datasets and records the absence of a second multihop benchmark as a limitation.

Prior question IDs are collected from Project 2's original traces and upgrade manifests. They are excluded before splitting. SQuAD also excludes previously used article titles. Available groups are SHA-256 ordered with a project-specific salt and assigned to development, validation and evaluation thirds. Questions are independently hash-ordered within each group pool, then the first 32/32/128 are retained. Counts are per dataset. Duplicate normalized question text is checked across partitions; original duplicate counts, group counts, IDs, hashes and annotation defects are recorded in the data-validation report. SQuAD answer spans are checked against original text. HotpotQA can still share Wikipedia pages across question groups; pretrained benchmark exposure cannot be excluded.

## Controllers and operational boundaries

The deployable `Task` contains only ID, question, documents and sentences. Gold answers and evidence labels enter scoring outside the controller. Oracle evidence enters through an explicit diagnostic-only argument and is never exposed to model action selection.

Fixed RAG executes one development-selected retrieval stage. Rules start with BM25 and request dense retrieval or reranking when document diversity or lexical question coverage is low. Plan-and-execute asks the planner for at most two structured actions before it sees evidence. The reactive agent chooses one action at a time after inspecting the latest evidence. Verification-guided control generates and checks a candidate after each changed memory, stops when the prespecified check passes, and otherwise permits another model action. It rejects low-support or unanchored final answers. These strategies have different control logic rather than different names for the same loop.

Allowed actions are a bounded JSON schema. Search tools accept a short query; fetch, expansion and title-link lookup accept an exact source title. Expansion finds the passage with greatest query-token overlap in that source and returns a bounded neighborhood around it. Without a query it defaults to the start of the source. Graph edges are deterministic case-insensitive mentions of another candidate title in source text. They are navigational hints, not extracted verified relationships. No model-generated graph facts are introduced.

The controller enforces step, call, token, context, memory and failure limits in Python. A repeated action is rejected. Invalid JSON and unknown tools cannot become executable commands. The tool registry has no filesystem, shell, network or code-execution capability. Retrieved strings remain data. These boundaries limit operational effects but do not establish resistance to answer contamination. The injected-instruction ablation is one synthetic perturbation family, not comprehensive security validation.

The action model sees the latest three stored passages, each shortened to 180 characters, the candidate titles, and up to 600 characters of the last two trace events. Full passages remain in evidence memory and generation prompts. This small action-state view can hide a bridge fact. The context-size ablation changes answer packing, not this fixed planner view. Neither selected benchmark supplies optimal-tool labels or independently annotated conflicting-document pairs, so tool choices are assessed through downstream answers, source labels and bounded perturbations.

## Models, prompts and source attribution

The six pinned local snapshots are FLAN-T5-base, Qwen3-0.6B, Qwen3-1.7B, BGE-small-en-v1.5, MS MARCO MiniLM-L6 reranking and DeBERTa-v3-small NLI. The lock records exact revisions, file sizes, hashes and model-card links. FLAN, Qwen and the cross-encoders use Apache 2.0 model licenses; BGE uses MIT. Local Safetensors/Transformers inference does not load remote code. Existing weights and package overlays are opened read-only; no paid service is used.

FLAN-T5-base is the prespecified answer generator, informed by Project 2's practical comparison. All three instruction models are evaluated as planners on eight development questions per dataset. The initial pilot minimized invalid actions, but that preferred a planner that rarely gathered useful evidence. Before any held-out evaluation, the prompt gained candidate titles and clearer lookup schemas, deployable outputs without sources became abstentions, and planner utility changed to pooled F1 plus 0.10 evidence recall minus 0.02 invalid actions and 0.01 calls. The original pilot remains local. SQuAD unanswerable cases affect the utility, so abstention prevalence can influence selection. A separate small answer-model comparison is exploratory. Query rewriting is the search-query field produced by the selected planner; it is not another independently trained module. BGE encodes normalized document vectors with 256-token truncation and prepends its documented instruction to queries. Fusion uses reciprocal rank fusion with constant 60. MiniLM reranks up to 12 fused candidates with a 384-token limit. Search returns two passages per call.

Generators use CUDA float16 where available, with no quantization. Retrieval encoders, reranking and NLI use their default float32 weights. FLAN uses its sequence-to-sequence tokenizer and a 512-token input ceiling. Qwen applies its chat template with `enable_thinking=False` and a 2048-token ceiling. Both decode greedily in this controlled study; this intentionally differs from Qwen's recommended sampling settings and can affect results. Every actual prompt, token count, raw response, parser failure and action is retained in local traces. The config contains token ceilings and fixed prespecified thresholds. No hidden reasoning text is requested or treated as evidence.

The answer prompt requests a short answer or UNKNOWN. Each nonempty answer receives a lexical best-overlap citation from the actual packed context. These are post hoc source assignments, not faithful model-generated attribution. A second FLAN call writes one declarative claim from the question and proposed answer. NLI checks the actual generated claim against the cited passage, records contradiction and truncation, and a literal answer anchor is required by the verification gate. Claim rewriting can itself change the proposed meaning. NLI can reward an irrelevant but entailed statement, and literal anchoring can reject valid paraphrases. Claim support is a model diagnostic, not independent annotation or proof of correctness.

All retrieval actions and generative calls are retained. In the verification-guided loop, cumulative verifier time includes intermediate checks, but only the final returned proposal's NLI probabilities are saved. Earlier probabilities are not available as original per-attempt measurements. The post-run all-window replay is a separate diagnostic, not a reconstruction of those earlier gate scores. Persisting a complete per-attempt NLI history remains an engineering limitation.

## Experiment stages and uncertainty

The planner pilot precedes full development retrieval comparison. BM25, dense, hybrid and reranking are compared on 32 development items per dataset; the highest pooled F1 fixes the reference retrieval tool. All five strategies then run on development and diagnostic validation partitions. Validation does not tune the prespecified thresholds. A freeze records the source/config/model fingerprint and selected planner and retrieval tool before evaluation begins. The seven main conditions include no-retrieval and oracle-document controls, each on 128 held-out questions per dataset. Oracle uses gold source documents, not gold answer spans or guaranteed complete context.

Prespecified ablations use the first 32 evaluation questions per dataset: one step, two calls, 280 context tokens, disabled memory deduplication, search-only registry, BM25-only registry, alternative verification cutoffs, empty first result, irrelevant first result and an injected instruction. Compare these with the matching first 32 reference questions, not full-sample averages. The fixed versus multi-step contrast also changes control and queries; it does not isolate retrieval count alone. A full Cartesian grid, larger quantized models, multiple timing repetitions and external multihop replication are deferred.

A step cap ends the action loop and permits an answer from current memory if tokens remain. An attempted call beyond the call budget, or an inference beyond the token budget, produces abstention. The two-call ablation therefore includes this conservative termination policy; its answer changes are not an isolated causal effect of seeing fewer passages.

Answer EM and token F1 use normalized strings with HotpotQA's yes/no mismatch convention. Evidence recall scores original source titles in the packed context. Supporting-fact recall requires complete original sentence containment and excludes invalid indices. Citation precision/recall compares cited titles with annotation labels and does not prove entailment. Coverage, selective EM and false-answer rates accompany abstention scores. The report distinguishes valid safe budget termination from a runaway loop; the latter cannot occur in the finite loop, although premature termination can harm correctness.

Two thousand paired bootstrap replicates resample HotpotQA questions and SQuAD article groups. Intervals are descriptive, pointwise and unadjusted for multiple comparisons. Small development samples and few SQuAD evaluation groups limit precision. The always-abstain comparator is calculated on the same items. Additional-retrieval evidence gain and duplicate-evidence frequency are annotation-based diagnostics, not causal estimates of whether a call was necessary.

Per-question wall time includes index creation, encoding on first use, planning, retrieval, generation, claim rewriting and NLI. Stage timing records the corresponding work; model loading is separate. CUDA synchronization bounds generation/NLI, while NumPy retrieval outputs synchronize their own device transfers. Process peak working set and CUDA allocation/reservation peaks describe the whole sequential run. They are not isolated method memory costs. Configurations run in fixed order with warm caches and uncontrolled background load. Cached predictions retain original inference timings; checkpoint lookup time is never reported as inference speed.

## Preservation and publication

Predictions are atomic, per-question checkpoints keyed by source, config, model aliases and question IDs. A row hash and task hash detect changed inputs. Completed runs are reused. Failed runs retain exception records; interrupted pilot attempts and later source fixes remain local rather than being relabeled successful. Published artifacts include code, configs, locks, aggregate reports, tests and one output-free public notebook. Raw questions, passage text, model weights, indexes, traces, package files and the executed notebook are excluded. Publication verifies test results, hashes, notebook cell identity, experiment-to-report reconstruction, staging scope, byte normalization and remote bytes without rewriting history.
